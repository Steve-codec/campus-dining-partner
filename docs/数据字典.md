# 校园饭搭子组局与推荐系统数据字典

本字典覆盖 step3 至 step6，与关系模式共用字段名，并已补齐 SQL 类型、长度、可空性和默认值。业务条件以[数据库设计](./数据库设计.md)第 2 至 10 节为准，逐表字段与约束执行该文档第 17 至 19 节和[数据库实现规格](./数据库实现规格.json)。

## 1 持久化数据项

相同字段名在多张表中表示同一种数据项。各类编号为正整数，时间精确到秒，均按北京时间解释。`NULL` 表示没有填写或该事件尚未发生。“无”表示不声明 DEFAULT，写入时必须提供值；自增编号由数据库生成。VARCHAR 长度以字符数计，全部文本采用 utf8mb4_0900_as_cs 排序规则。

| 编号 | 字段名 | SQL 类型 | 允许 NULL | 默认值 | 含义与逻辑取值 |
| --- | --- | --- | --- | --- | --- |
| I01 | `user_id` | `INT UNSIGNED` | 否 | users 中自增；引用列无默认值 | 用户唯一编号 |
| I02 | `username` | `VARCHAR(32)` | 否 | 无 | 登录用户名，去除首尾普通空格后保存，区分大小写与重音，且用户间唯一 |
| I03 | `nickname` | `VARCHAR(32)` | 否 | 无 | 用户昵称，必填，允许重名 |
| I04 | `password_hash` | `VARCHAR(255)` | 否 | 无 | 后端根据登录密码生成的密码摘要 |
| I05 | `preferred_slot` | `VARCHAR(10)` | 是 | `NULL` | 单个偏好时段；BREAKFAST 为早餐，LUNCH 为午餐，DINNER 为晚餐，LATE_NIGHT 为夜宵；NULL 表示无时段偏好 |
| I06 | `created_at` | `DATETIME(0)` | 否 | `CURRENT_TIMESTAMP` | 记录创建时间；在 users 中为注册时间，在 dining_events 中为饭局发布时间 |
| I07 | `canteen_id` | `INT UNSIGNED` | 否 | canteens 中自增；引用列无默认值 | 食堂唯一编号；在 stalls 中表示所属食堂 |
| I08 | `canteen_name` | `VARCHAR(64)` | 否 | 无 | 食堂显示名称 |
| I09 | `stall_id` | `INT UNSIGNED` | 否 | stalls 中自增；引用列无默认值 | 档口唯一编号；在饭局和收藏中标识所选档口 |
| I10 | `stall_name` | `VARCHAR(64)` | 否 | 无 | 档口显示名称 |
| I11 | `event_id` | `INT UNSIGNED` | 否 | dining_events 中自增；引用列无默认值 | 饭局唯一编号 |
| I12 | `host_user_id` | `INT UNSIGNED` | 否 | 无 | 发起人用户编号，取值对应 users.user_id |
| I13 | `title` | `VARCHAR(100)` | 否 | 无 | 饭局标题，必填 |
| I14 | `meal_time` | `DATETIME(0)` | 否 | 无 | 计划就餐时间；发布与修改时必须晚于数据库当前时间 |
| I15 | `capacity` | `SMALLINT UNSIGNED` | 否 | 无 | 包含发起人的总人数上限，为 2 至 65535 的整数 |
| I16 | `description` | `VARCHAR(500)` | 是 | `NULL` | 饭局说明文本，NULL 表示未填写 |
| I17 | `cancelled_at` | `DATETIME(0)` | 是 | `NULL` | 取消时间，NULL 表示未取消 |
| I18 | `registration_status` | `VARCHAR(6)` | 否 | `'JOINED'` | JOINED 表示已报名，EXITED 表示已退出 |
| I19 | `last_joined_at` | `DATETIME(0)` | 否 | `CURRENT_TIMESTAMP` | 最近一次成功报名时间；发起人的初始值为饭局创建时间 |
| I20 | `last_exited_at` | `DATETIME(0)` | 是 | `NULL` | 最近一次退出时间，NULL 表示从未退出，再次报名时保留原值 |
| I21 | `tag_id` | `INT UNSIGNED` | 否 | taste_tags 中自增；引用列无默认值 | 口味标签唯一编号 |
| I22 | `tag_name` | `VARCHAR(16)` | 否 | 无 | 标签名称，唯一；取清淡、香辣、麻辣、甜口、咸鲜、素食中的一个 |
| I23 | `favorited_at` | `DATETIME(0)` | 否 | `CURRENT_TIMESTAMP` | 当前收藏关联的建立时间；取消后再次收藏产生新的时间 |
| I24 | `rating` | `TINYINT UNSIGNED` | 否 | 无 | 饭局评分，为 1 至 5 的整数 |
| I25 | `content` | `VARCHAR(500)` | 是 | `NULL` | 评价文本，NULL 表示仅提交评分 |
| I26 | `reviewed_at` | `DATETIME(0)` | 否 | `CURRENT_TIMESTAMP` | 评价提交时间 |

登录请求中的原始密码和当前登录状态属于临时数据，不在以上十个关系中新增字段或数据表。

## 2 数据结构与数据存储

D1 至 D10 同时标识数据结构与对应数据存储。每个存储保存该结构的多条记录。D0 表示这十个存储的逻辑汇总。

| 编号 | 名称与关系名 | 完整组成 |
| --- | --- | --- |
| D1 | 用户 users | user_id, username, nickname, password_hash, preferred_slot, created_at |
| D2 | 食堂 canteens | canteen_id, canteen_name |
| D3 | 档口 stalls | stall_id, canteen_id, stall_name |
| D4 | 饭局 dining_events | event_id, host_user_id, stall_id, title, meal_time, capacity, description, cancelled_at, created_at |
| D5 | 报名记录 registrations | event_id, user_id, registration_status, last_joined_at, last_exited_at |
| D6 | 口味标签 taste_tags | tag_id, tag_name |
| D7 | 用户口味偏好 user_taste_preferences | user_id, tag_id |
| D8 | 饭局标签 event_taste_tags | event_id, tag_id |
| D9 | 档口收藏 stall_favorites | user_id, stall_id, favorited_at |
| D10 | 饭局评价 event_reviews | event_id, user_id, rating, content, reviewed_at |

报名记录、用户口味偏好、饭局标签、档口收藏和饭局评价使用两端编号组成的复合主键，键定义见数据库设计第 14.3 节。

## 3 外部数据流

E1 表示学生，E2 表示通过初始化脚本提供基础资料的小组维护者。请求中的当前用户编号来自登录身份。下表的组成按请求操作选择，发布内容、筛选条件和评价条件执行数据库设计中已经定义的规则。

| 编号 | 名称与流向 | 数据组成 |
| --- | --- | --- |
| F01 | 账户请求：E1 → P1 | 操作类型为注册、登录或退出登录；注册携带用户名、昵称、密码，登录携带用户名、密码，退出携带当前登录身份 |
| F02 | 账户结果：P1 → E1 | 操作结果与登录状态；注册成功返回用户编号，登录成功返回用户编号和昵称 |
| F03 | 饭局请求：E1 → P2 | 操作类型、当前用户编号、目标饭局编号；发布与修改携带标题、档口编号、计划就餐时间、人数上限、说明、口味标签编号集合；查询携带食堂编号、档口编号、计划日期、用餐时段、标签编号集合、饭局状态筛选条件 |
| F04 | 饭局结果：P2 → E1 | 操作结果；发布返回饭局编号，查询返回列表或详情、当前人数和剩余名额，本人发起记录查询返回饭局列表，本人报名记录查询返回饭局列表、报名状态、最近报名时间、最近退出时间和饭局状态，发起人名单查询返回用户编号、昵称、最近报名时间和发起人标识 |
| F05 | 报名退出请求：E1 → P3 | 操作类型为报名或退出、当前用户编号、饭局编号 |
| F06 | 报名退出结果：P3 → E1 | 操作结果、饭局编号、报名状态、最近报名时间、最近退出时间、当前报名人数和剩余名额 |
| F07 | 偏好收藏请求：E1 → P4 | 操作类型、当前用户编号；保存偏好携带口味标签编号集合和单个偏好时段，收藏与取消收藏携带档口编号，读取偏好与收藏列表携带当前用户编号 |
| F08 | 偏好收藏结果：P4 → E1 | 操作结果、口味偏好标签、偏好时段或收藏档口列表；收藏列表记录包含档口编号、档口名称和收藏时间 |
| F09 | 评价请求：E1 → P5 | 当前用户编号、饭局编号、评分、评价文本 |
| F10 | 评价结果：P5 → E1 | 操作结果；成功时返回饭局编号、用户编号、评分、评价文本和评价时间 |
| F11 | 统计推荐请求：E1 → P6 | 操作类型为个人统计、饭局推荐或热力图；携带当前用户编号，热力图可携带单个食堂编号 |
| F12 | 统计推荐结果：P6 → E1 | 个人统计返回发起次数与参与次数；推荐返回排序后的饭局、匹配分、当前人数和剩余名额；热力图返回星期编号、小时编号和饭局数量 |
| F13 | 基础资料：E2 → P7 | 食堂编号与名称、档口编号与名称及所属食堂编号、六个口味标签的编号与名称 |
| F14 | 导入结果：P7 → E2 | 操作结果、成功导入的食堂条数、档口条数和口味标签条数 |

F03 的操作类型为发布、修改、删除、取消、列表查询、详情查询、本人发起记录查询、本人报名记录查询、发起人名单查询。F07 的操作类型为读取偏好、保存偏好、收藏、取消收藏、读取收藏列表。

第二层图将 F05 拆为 F05.1 报名请求与 F05.2 退出请求，将 F06 拆为 F06.1 报名结果与 F06.2 退出结果；拆分后的组成不超出对应上层数据流。

## 4 处理逻辑

| 编号 | 处理 | 读取存储 | 写入存储 |
| --- | --- | --- | --- |
| P1 | 账户 | D1 | D1 |
| P2 | 饭局管理与查询 | D1、D2、D3、D4、D5、D6、D8 | D4、D5、D8 |
| P3 | 报名与退出 | D4、D5 | D5 |
| P4 | 偏好与收藏 | D1、D3、D6、D7、D9 | D1、D7、D9 |
| P5 | 评价 | D4、D5、D10 | D10 |
| P6 | 统计与推荐 | D1、D2、D3、D4、D5、D6、D7、D8、D9 | 无 |
| P7 | 基础资料导入 | 无 | D2、D3、D6 |

- P1：注册建立用户记录；登录由后端校验凭据并建立登录状态；退出结束登录状态。登录和退出不改变业务记录。
- P2：发布建立饭局与饭局标签，发起人报名记录由饭局 AFTER INSERT 触发器自动生成；修改更新饭局内容与标签；删除移除饭局、标签和发起人报名记录；取消写入取消时间；查询组合地点、用户、标签与报名人数，同时支持本人发起记录与本人报名记录查询。删除与取消的条件执行数据库设计第 6 节。
- P3.1：读取饭局状态、人数上限、本人报名记录和当前人数；满足报名条件后首次插入报名记录，或将原退出记录恢复为已报名并更新最近报名时间。名额检查和写入在同一事务中完成。
- P3.2：读取饭局发起人、状态和本人报名记录；满足退出条件后将原记录改为已退出，写入最近退出时间。名额由记录状态变化释放。
- P4：读取与保存单个时段偏好及口味标签关联；收藏建立关联，取消收藏删除关联；读取时返回本人当前偏好或收藏列表。
- P5：读取饭局、本人报名记录和已有评价；满足数据库设计第 9 节条件后建立评价记录。
- P6：按数据库设计第 8、10 节完成推荐、个人次数统计和星期小时汇总，仅返回计算结果。
- P7：通过初始化脚本写入食堂、档口和六个口味标签，返回写入条数。

## 5 派生数据项

以下数据不作为本阶段十个关系中的独立存储字段。

| 名称 | 定义 |
| --- | --- |
| 饭局业务状态 | cancelled_at 有值为已取消；否则数据库当前时间早于 meal_time 为未开始，到达或超过 meal_time 为已开始 |
| 用餐时段 | 按 meal_time 的北京时间时刻映射为早餐、午餐、晚餐、夜宵，边界见数据库设计第 3 节 |
| 当前报名人数 | 同一 event_id 下 registration_status 为 JOINED 的记录数，包含发起人 |
| 剩余名额 | capacity 减去当前报名人数 |
| 推荐匹配分 | 3 × 共同口味标签数量 + 2 × 收藏档口命中值 + 偏好时段命中值 |
| 发起次数 | 当前用户发起且 cancelled_at 为空的现存饭局数量 |
| 参与次数 | 当前用户拥有 JOINED 记录、cancelled_at 为空且 meal_time 已到的饭局数量，包含本人发起的饭局 |
| 星期与小时分组键 | 按 meal_time 提取星期编号与小时编号；星期一为 1，星期日为 7，小时为 0 至 23 |
| 热力图饭局数量 | 对 cancelled_at 为空的饭局按星期与小时分组计数；指定食堂时通过档口所属食堂筛选，无记录格为 0 |
